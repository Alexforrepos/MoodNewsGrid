# MoodNewsGrid

Веб-приложение, которое получает реальные новости из открытых RSS-источников и позволяет читать их в разных эмоциональных режимах.

Для каждой новости можно выбрать настроение:

* Нейтрально
* Радостно
* Грустно
* Иронично
* Драматично

Исходный текст новости сохраняется отдельно, а эмоциональная версия генерируется только при необходимости с помощью LLM. Для каждого сочетания `новость + настроение` результат сохраняется в базе данных, поэтому повторно обращаться к AI не требуется.

## Возможности

* получение реальных новостей из открытых RSS-источников;
* сохранение новостей в PostgreSQL;
* отображение новостей в адаптивном grid;
* переключение эмоционального режима;
* генерация эмоциональной версии новости через LLM;
* просмотр оригинала и переписанного текста рядом;
* ссылка на исходный материал;
* сохранение сгенерированных вариантов в БД;
* автоматическая проверка ключевых фактов после генерации.

# Как работает приложение

Общий flow выглядит следующим образом:


RSS-источники
      ↓
RssNewsFetcher
      ↓
NewsService
      ↓
PostgreSQL
      ↓
NewsController
      ↓
Razor Views

Если для выбранного настроения версия новости ещё не существует:


News
  ↓
LlmMoodRewriter
  ↓
FactChecker
  ↓
NewsRewrite
  ↓
PostgreSQL


При следующем запросе готовая версия берётся из базы.

# Источники новостей

Приложение получает новости из открытых RSS-лент.

В текущей реализации используются:

* Лента.ру
* РИА Новости
* Habr

RSS-источник передаёт как минимум:

* заголовок;
* ссылку на оригинал;
* дату публикации;
* краткое содержание новости.

Для каждой сохранённой новости также записывается название источника.

Таким образом, пользователь всегда может перейти к оригинальному материалу.

> Важно: приложение работает с содержимым, которое доступно в RSS, прежде всего с `summary/description`. Оно не пытается скрыто загружать или переписывать весь текст страницы оригинального СМИ.

# Хранение данных

Используется PostgreSQL.

Основные сущности:

## `NewsItem`

Содержит оригинальную новость:

Id
Title
OriginalText
SourceUrl
SourceName
PublishedAt
FetchedAt


Оригинальный текст после сохранения не изменяется.

## `NewsRewrite`

Содержит конкретную эмоциональную версию:


Id
NewsItemId
Mood
RewrittenText
FactsCheckPassed
FactsCheckIssues
CreatedAt

Между сущностями установлена связь:


NewsItem 1 ───── * NewsRewrite


Для пары:


NewsItem + Mood


создаётся уникальный индекс.

Это позволяет хранить максимум одну версию каждого настроения для конкретной новости и использовать БД как кэш результатов AI.

Например:


News #42
 ├── Neutral
 ├── Joyful
 ├── Sad
 ├── Ironic
 └── Dramatic

# Как генерируется эмоциональный текст

Для генерации используется LLM через OpenRouter.

В приложение передаются:

1. оригинальный текст новости;
2. выбранное настроение;
3. инструкции по сохранению фактов.

Основное требование к prompt:

> изменить только стиль и эмоциональную подачу, не добавляя и не изменяя фактическую информацию.

В prompt отдельно указывается необходимость сохранять:

* имена;
* даты;
* числа;
* места;
* цитаты;
* названия организаций;
* события и их фактическую последовательность.

Пример концепции:


Original news
      +
Selected mood
      ↓
     LLM
      ↓
Rewritten news


При этом оригинальная новость никогда не заменяется сгенерированной версией.

---

# Контроль сохранения фактов

Для дополнительного контроля после генерации запускается `RegexFactChecker`.

Проверяются ключевые элементы исходного текста, в частности:

* числа;
* некоторые даты;
* цитаты;
* слова, похожие на имена собственные.

Если обязательные элементы не обнаружены в переписанном тексте, результат помечается как не прошедший проверку, а найденные проблемы сохраняются в `FactsCheckIssues`.

Пример:


Original:
Компания X инвестировала 15 млн рублей в проект в Москве.

Rewrite:
Компания X радостно инвестировала 15 млн рублей в проект в Москве.

Result:
FactsCheckPassed = true


Если число изменится:


15 млн → 25 млн


проверка должна обнаружить несоответствие.

---

## Ограничения проверки фактов

Используемая проверка является **эвристической**, а не полноценной семантической проверкой фактов.

Regex-проверка хорошо подходит для контроля некоторых структурированных элементов, например чисел, но не может гарантировать, что LLM полностью сохранила смысл предложения.

Например, изменение:


Компания открыла завод.


на:


Компания закрыла завод.


может не быть обнаружено простой проверкой наличия ключевых слов.

Поэтому в проекте используются два уровня защиты:

1. подробная инструкция для LLM не менять факты;
2. пост-проверка критичных токенов и значений.

Это снижает вероятность ошибки, но не является математической гарантией семантической идентичности.

# Почему переписывание не происходит заранее

Эмоциональные версии не создаются вручную.

Они генерируются динамически при первом запросе конкретной комбинации:


NewsItem + Mood


После успешной генерации результат сохраняется в PostgreSQL.

Например:


Пользователь открыл новость
        ↓
Выбрал "Иронично"
        ↓
Проверяем БД
        ↓
Rewrite отсутствует
        ↓
LLM
        ↓
FactChecker
        ↓
Сохраняем результат


При повторном открытии:


Пользователь выбрал "Иронично"
        ↓
Rewrite уже существует
        ↓
Берём из PostgreSQL


Таким образом, одна и та же новость не отправляется в LLM при каждом просмотре.

---

# Защита от дубликатов

Для `NewsItem` установлен уникальный индекс по `SourceUrl`.

Это позволяет не сохранять одну и ту же RSS-новость несколько раз, если она повторно пришла из источника.

Для `NewsRewrite` используется уникальность:


NewsItemId + Mood


Таким образом, для одной новости невозможно случайно создать несколько вариантов одного и того же настроения.

# Запуск локально

## Требования

Для локального запуска необходимы:

* .NET 10 SDK;
* PostgreSQL;
* API key для выбранного LLM-провайдера.

### 1. Клонировать репозиторий

bash
git clone <https://github.com/Alexforrepos/MoodNewsGrid>
cd MoodNewsGrid


### 2. Настроить подключение к PostgreSQL

В конфигурации приложения необходимо указать connection string.

Например:


Host=localhost
Port=5432
Database=moodnews
Username=postgres
Password=...


### 3. Настроить API key

API key не должен храниться в Git.

Для локального запуска его можно передать через переменную окружения:

bash
Llm__ApiKey=<YOUR_API_KEY>


### 4. Запустить приложение

bash
dotnet run --project MoodNewsGrid.Web


После запуска приложение будет доступно по адресу, который выведет ASP.NET Core.

# Запуск через Docker Compose

Проект также содержит `Dockerfile` и `docker-compose.yml`.

Запуск:

bash
docker compose up --build


PostgreSQL и веб-приложение запускаются как отдельные контейнеры.

API key передаётся в контейнер через переменную окружения:

bash
LLM_API_KEY=<YOUR_API_KEY> docker compose up --build


Это позволяет не записывать секрет непосредственно в `docker-compose.yml`.

# Решения и компромиссы

## Почему RSS

RSS позволяет получать реальные новости без необходимости реализовывать отдельный scraping каждой страницы СМИ.

Преимущества:

* открытые источники;
* простой формат;
* ссылка на оригинал;
* дата публикации;
* заголовок и краткий текст;
* меньше зависимости от HTML-разметки конкретного сайта.

Ограничение: RSS обычно содержит краткое описание, а не полный текст статьи.

---

## Почему результаты AI сохраняются в БД

Генерация текста через LLM — внешняя операция, которая может быть медленной и иметь ограничения по количеству запросов.

Поэтому результат сохраняется и повторно используется.

Это одновременно:

* уменьшает количество запросов к AI;
* уменьшает стоимость;
* ускоряет повторный просмотр;
* делает результат стабильным для пользователя.

---

## Почему оригинал и rewrite хранятся отдельно

Это позволяет всегда сравнить:


Original
    ↕
Rewrite


и исключает ситуацию, когда AI случайно заменит единственную сохранённую версию новости.

Оригинальный текст является источником истины, а rewrite — производным представлением.

---

# Использование AI

AI используется только для изменения подачи уже существующей новости.

AI не используется для:

* генерации исходных новостей;
* генерации источников;
* генерации дат;
* генерации ссылок;
* наполнения базы выдуманными материалами.

Исходные новости приходят из реальных RSS-источников.

Для генерации эмоциональных версий используется LLM через OpenRouter.

Модель задаётся конфигурацией приложения и может быть заменена без изменения основной бизнес-логики благодаря интерфейсу `IMoodRewriter`.

# Что можно улучшить

Текущая реализация является тестовым проектом, поэтому некоторые решения намеренно остаются простыми.

В дальнейшем можно улучшить:

* заменить regex fact checking на структурированное извлечение и сравнение фактов;
* выполнять генерацию rewrite в background job;
* добавить retry и обработку rate limits LLM API;
* добавить unit/integration tests;
* использовать ViewModels вместо `ViewBag`;
* добавить пагинацию новостей;
* добавить более строгую нормализацию RSS;
* хранить enum `Mood` как строку вместо integer;
* добавить мониторинг ошибок источников;
* вынести применение миграций из старта веб-приложения в deployment step.

# Итог

Проект реализует основной сценарий тестового задания:

| Требование                    | Реализация                          |
| ----------------------------- | ----------------------------------- |
| Минимум 10 реальных новостей  | RSS-источники                       |
| Хранение новостей             | PostgreSQL + EF Core                |
| Grid                          | Razor View + CSS Grid               |
| Переключение настроения       | `Mood` + UI                         |
| Исходный и переписанный текст | `NewsItem` + `NewsRewrite`          |
| Ссылка на оригинал            | `SourceUrl`                         |
| AI-переписывание              | `IMoodRewriter` / OpenRouter        |
| Контроль фактов               | Prompt + `RegexFactChecker`         |
| Кэширование AI-результатов    | Уникальная пара `NewsItemId + Mood` |
| Docker                        | Dockerfile + Docker Compose         |

Главный принцип проекта:


Real News
   ↓
Store Original
   ↓
Choose Mood
   ↓
LLM Rewrite
   ↓
Fact Check
   ↓
Store Rewrite
   ↓
Compare Original / Rewrite


При этом **оригинальная новость всегда остаётся неизменной**, а эмоциональная версия является отдельным сохранённым результатом.
